## 🎯 Part 1: Data Link Layer এর পরিচয়

### Data Link Layer কি?

```
OSI Model:
┌─────────────────────┐
│ 7. Application      │
│ 6. Presentation     │
│ 5. Session          │
│ 4. Transport        │
│ 3. Network          │
│ 2. Data Link ◄──────│ আমরা এখানে
│ 1. Physical         │
└─────────────────────┘
```

### মূল দায়িত্ব:

**১. Node-to-Node Delivery:**
- সরাসরি সংযুক্ত দুই ডিভাইসের মধ্যে data পাঠানো
- Physical addressing (MAC) ব্যবহার করে

**২. Framing:**
- Network layer থেকে packets নিয়ে frames বানানো
- Header ও Trailer যোগ করা

**৩. Error Detection:**
- Transmission এ error হয়েছে কিনা check করা
- Corrupted frames বাতিল করা

**৪. Flow Control:**
- Sender ও Receiver এর মধ্যে speed সমন্বয়

**৫. Access Control:**
- Shared medium এ কে কখন পাঠাবে তা নিয়ন্ত্রণ

### Two Sub-layers:

```
┌────────────────────────────────┐
│   LLC (Logical Link Control)   │
│   - Error Control              │
│   - Flow Control               │
│   - Framing                    │
├────────────────────────────────┤
│   MAC (Media Access Control)   │
│   - Physical Addressing        │
│   - Access Control             │
└────────────────────────────────┘
```

**LLC (Logical Link Control):**
```
কাজ:
- Network Layer এর সাথে interface করে
- Error checking এবং recovery
- Flow control maintain করে
- Protocol multiplexing

IEEE 802.2 standard অনুসরণ করে
```

**MAC (Media Access Control):**
```
কাজ:
- Frame assembly/disassembly
- MAC addressing
- Media access management
- Error detection (CRC যোগ করে)

বিভিন্ন standard:
- IEEE 802.3 (Ethernet)
- IEEE 802.11 (Wi-Fi)
- IEEE 802.15 (Bluetooth)
```

## 🔢 Part 2: MAC Address - সম্পূর্ণ বিশ্লেষণ

### MAC Address কি?

```
MAC = Media Access Control Address
অন্য নাম:
- Physical Address
- Hardware Address
- Burned-in Address (BIA)
- Ethernet Address
```

### MAC Address এর গঠন:

```
Total: 48 bits = 6 bytes = 12 Hexadecimal digits

Format 1 (সাধারণ): AA:BB:CC:DD:EE:FF
Format 2 (Cisco):   AABB.CCDD.EEFF
Format 3 (Windows): AA-BB-CC-DD-EE-FF

Binary তে:
10101010 10111011 11001100 11011101 11101110 11111111
```

### OUI এবং NIC বিভাগ:

```
┌─────────────────────────────────────────────────┐
│           48-bit MAC Address                    │
├────────────────────────┬────────────────────────┤
│   OUI (24 bits)        │   NIC (24 bits)        │
│ Organizationally       │ Network Interface      │
│ Unique Identifier      │ Controller Specific    │
├────────────────────────┼────────────────────────┤
│    AA : BB : CC        │    DD : EE : FF        │
│   (Manufacturer)       │   (Device Number)      │
└────────────────────────┴────────────────────────┘
```

**বিখ্যাত নির্মাতাদের OUI:**

```
┌──────────────┬─────────────────┐
│ Company      │ OUI Prefix      │
├──────────────┼─────────────────┤
│ Cisco        │ 00:1A:A1        │
│ Dell         │ 00:14:22        │
│ HP           │ 00:1E:0B        │
│ Apple        │ AC:DE:48        │
│ Intel        │ 00:1B:21        │
│ D-Link       │ 00:1B:11        │
│ TP-Link      │ EC:08:6B        │
│ Huawei       │ 00:E0:FC        │
└──────────────┴─────────────────┘
```

### MAC Address এর প্রথম Byte বিশ্লেষণ:

```
Binary: 10101010 (AA in hex)
        ││││││││
        │││││││└─ Bit 0 (LSB)
        ││││││└── Bit 1
        │││││└─── Bit 2
        ││││└──── Bit 3
        │││└───── Bit 4
        ││└────── Bit 5
        │└─────── Bit 6
        └──────── Bit 7 (MSB)

Important Bits:
Bit 0 (LSB): I/G bit (Individual/Group)
  - 0 = Unicast (একক ডিভাইস)
  - 1 = Multicast (একাধিক ডিভাইস)

Bit 1: U/L bit (Universal/Local)
  - 0 = Globally Unique (নির্মাতা assigned)
  - 1 = Locally Administered (manually set)
```

### MAC Address এর প্রকারভেদ:

**1. Unicast MAC Address:**
```
Example: A0:B1:C2:D3:E4:F5
Binary first byte: 10100000 (Bit 0 = 0)

ব্যবহার:
- নির্দিষ্ট একটি device কে পাঠানোর জন্য
- সবচেয়ে সাধারণ type

কিভাবে চিনবেন:
- প্রথম byte এর শেষ bit = 0
- Example: A0, 02, 44, 66, 88, AA, CC, EE
```

**2. Multicast MAC Address:**
```
Example: 01:00:5E:7F:00:01
Binary first byte: 00000001 (Bit 0 = 1)

ব্যবহার:
- একই group এর একাধিক device
- Video streaming, IPTV
- Routing protocols (OSPF, EIGRP)

IPv4 Multicast MAC বানানোর নিয়ম:
Step 1: 01:00:5E দিয়ে শুরু (fixed)
Step 2: IP Multicast এর শেষ 23 bits নিয়ে বাকি তৈরি

Example:
IP: 224.0.0.1 (OSPF All Routers)
MAC: 01:00:5E:00:00:01

কিভাবে চিনবেন:
- প্রথম byte = odd number
- Example: 01, 03, 05, 07, 09, 0B, 0D, 0F
```

**3. Broadcast MAC Address:**
```
Address: FF:FF:FF:FF:FF:FF
Binary: সব bits = 1

ব্যবহার:
- Network এর সব device কে একসাথে পাঠানো
- ARP requests
- DHCP Discovery
- NetBIOS name resolution

বৈশিষ্ট্য:
- শুধুমাত্র একটি broadcast MAC আছে
- Local network এর মধ্যে সীমাবদ্ধ
- Router broadcast forward করে না
```

### Locally Administered vs Globally Unique:

**Globally Unique (Universal):**
```
Example: 00:1A:2B:3C:4D:5E
Binary first byte: 00000000 (Bit 1 = 0)

বৈশিষ্ট্য:
- Manufacturer assign করে
- Worldwide unique guarantee
- ROM এ burned থাকে
- পরিবর্তন করা যায় না (hardware level)
```

**Locally Administered:**
```
Example: 02:1A:2B:3C:4D:5E
Binary first byte: 00000010 (Bit 1 = 1)

বৈশিষ্ট্য:
- User/Admin manually set করে
- Virtual interfaces (VLAN, VPN)
- MAC spoofing
- Duplicate হতে পারে (same network এ সমস্যা)

কখন ব্যবহার হয়:
- Virtual machines
- Docker containers
- VPN interfaces
- Load balancers
```

**Windows এ:**
```

2. Properties → Advanced
3. "Network Address" বা "Locally Administered Address"
4. নতুন MAC enter করুন
```


**কেন MAC spoofing করা হয়:**
```
Legitimate ব্যবহার:
- Privacy protection
- Network testing
- Bypass MAC filtering
- Virtual environments

Malicious ব্যবহার:
- Identity theft
- Bypass security
- Network attacks (ARP spoofing)

নৈতিক দিক:
- নিজের network এ = ঠিক আছে
- অন্যের network এ = illegal
```

## 📦 Part 3: Ethernet Frame Structure

### Ethernet Frame - সম্পূর্ণ গঠন:

```
┌──────────┬─────┬───────────┬───────────┬──────┬──────┬─────┬────────┐
│ Preamble │ SFD │  Dest.    │  Source   │ Type/│ Data │ Pad │  FCS   │
│ 7 bytes  │1 byte│   MAC     │   MAC     │Length│      │     │4 bytes │
│          │     │  6 bytes  │  6 bytes  │2 byte│46-1500│    │        │
└──────────┴─────┴───────────┴───────────┴──────┴──────┴─────┴────────┘
   56 bits   8 bits  48 bits    48 bits   16 bits  Variable  32 bits

Total Frame Size: 64 bytes থেকে 1518 bytes
(Preamble ও SFD বাদে: 64-1518 bytes)
```

### প্রতিটি Field এর বিস্তারিত:

---

#### 1. Preamble (প্রস্তাবনা) - 7 bytes

```
Pattern: 10101010 10101010 10101010 10101010 10101010 10101010 10101010
         (56 bits of alternating 1s and 0s)

Hexadecimal: AA AA AA AA AA AA AA

উদ্দেশ্য:
1. Clock Synchronization:
   - Sender ও Receiver এর clock align করে
   - Timing reference তৈরি করে

2. Signal Stabilization:
   - Physical layer এর signal settle হতে দেয়
   - Receiver এর circuitry prepare করে

3. Bit Pattern Recognition:
   - Receiver বুঝতে পারে data আসছে
   - Automatic Gain Control (AGC) adjust করে

কেন 10101010 pattern:
- Maximum transition (0→1, 1→0)
- Clock recovery সহজ
- Signal quality test করা যায়
```

#### 2. SFD (Start Frame Delimiter) - 1 byte

```
Pattern: 10101011
Hexadecimal: AB

উদ্দেশ্য:
1. Frame এর প্রকৃত শুরু নির্দেশ করে
2. Preamble শেষ হয়েছে বুঝায়
3. শেষের দুই bit (11) দিয়ে signal দেয় যে এখন data আসবে

Receiver এর action:
- এই byte দেখলেই পরবর্তী byte থেকে MAC address পড়া শুরু করে
- Timing adjustment সম্পূর্ণ করে
```

#### 3. Destination MAC Address - 6 bytes

```
Example: 00:1A:2B:3C:4D:5E
Size: 48 bits = 6 bytes

কাজ:
1. Frame কোথায় যাবে তা নির্দেশ করে
2. Switch এই address দেখে forwarding decision নেয়
3. Network card এটি match করে frame receive করবে কিনা decide করে

প্রকারভেদ:
- Unicast: নির্দিষ্ট একটি device
- Multicast: একাধিক device (group)
- Broadcast: FF:FF:FF:FF:FF:FF (সবাই)

Receiver এর check:
if (Dest_MAC == My_MAC || Dest_MAC == Broadcast || Dest_MAC == Subscribed_Multicast)
    Accept frame
else
    Discard frame
```

#### 4. Source MAC Address - 6 bytes

```
Example: A1:B2:C3:D4:E5:F6
Size: 48 bits = 6 bytes

কাজ:
1. Frame কোথা থেকে এসেছে তা জানায়
2. Reply পাঠানোর জন্য address provide করে
3. Switch এটি দেখে MAC table update করে
4. Security ও monitoring এ ব্যবহার হয়

Switch এর কাজ:
1. Source MAC পড়ে
2. কোন port থেকে এসেছে note করে
3. MAC Address Table এ entry যোগ/update করে
4. Aging timer reset করে

ARP Cache এ ব্যবহার:
- IP-to-MAC mapping তৈরি হয়
- Future communication সহজ হয়
```

#### 5. Type/Length Field - 2 bytes

```
Size: 16 bits = 2 bytes

দুই ধরনের ব্যবহার:

A) EtherType (যদি মান ≥ 1536 বা 0x0600):
   ┌──────────┬───────────────────────────┐
   │ Value    │ Protocol                  │
   ├──────────┼───────────────────────────┤
   │ 0x0800   │ IPv4                      │
   │ 0x0806   │ ARP                       │
   │ 0x0842   │ Wake-on-LAN               │
   │ 0x86DD   │ IPv6                      │
   │ 0x8100   │ VLAN-tagged frame (802.1Q)│
   │ 0x88CC   │ LLDP                      │
   │ 0x8863   │ PPPoE Discovery           │
   │ 0x8864   │ PPPoE Session             │
   └──────────┴───────────────────────────┘

B) Length (যদি মান ≤ 1500):
   - Data field এর actual length নির্দেশ করে
   - IEEE 802.3 frame এ ব্যবহার হয়
   - LLC header থাকে data এর শুরুতে

Example Analysis:
0x0800 = IPv4 packet inside
0x0806 = ARP request/reply inside
0x05DC (1500 decimal) = 1500 bytes data
```

#### 6. Data/Payload - 46 to 1500 bytes

```
Minimum: 46 bytes
Maximum: 1500 bytes (MTU - Maximum Transmission Unit)

Content:
- Network layer packet (IP packet)
- LLC header (802.3 frames এ)
- Upper layer data

Minimum Size Requirement:
┌─────────────────────────────────────────┐
│ কেন minimum 46 bytes?                   │
├─────────────────────────────────────────┤
│ Ethernet collision detection এর জন্য  │
│ Minimum frame = 64 bytes দরকার        │
│                                         │
│ Calculation:                            │
│ Dest MAC (6) + Source MAC (6) +        │
│ Type (2) + Data (46) + FCS (4) = 64    │
└─────────────────────────────────────────┘

যদি data < 46 bytes:
- Padding যোগ করা হয় (0x00 bytes)
- Example: 30 bytes data → 16 bytes padding যোগ

┌──────────────────────────────┐
│ Actual Data: 30 bytes        │
│ Padding: 16 bytes (0x00...)  │
│ Total: 46 bytes ✓            │
└──────────────────────────────┘

Maximum Size (MTU):
- Standard Ethernet: 1500 bytes
- Jumbo Frames: 9000 bytes (special config)
- Baby Giant: 2000 bytes (some vendors)

যদি data > MTU:
Network layer এ fragmentation হয়
```

#### 7. Frame Check Sequence (FCS) - 4 bytes

```
Size: 32 bits = 4 bytes
Algorithm: CRC-32 (Cyclic Redundancy Check)

কাজ:
- Error detection
- Data integrity verification
- Corruption check

CRC-32 Generation Process:

Step 1: Input
Frame = Dest MAC + Source MAC + Type + Data
(FCS ছাড়া বাকি সব)

Step 2: Polynomial
Generator Polynomial (G): 
x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1

Binary: 100000100110000010001110110110111
(33 bits)

Step 3: Calculation
┌─────────────────────────────────────┐
│ Sender:                             │
│ 1. Frame data এর শেষে 32 bits      │
│    zero append করে                 │
│ 2. Generator দিয়ে binary division  │
│    (XOR operation)                  │
│ 3. Remainder = FCS (32 bits)       │
│ 4. Original frame + FCS পাঠায়     │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ Receiver:                           │
│ 1. পুরো frame (data + FCS) নিয়ে   │
│    একই division করে               │
│ 2. Remainder check করে:           │
│    - Remainder = 0 → সঠিক ✓        │
│    - Remainder ≠ 0 → error ✗       │
│ 3. Error থাকলে frame discard      │
└─────────────────────────────────────┘

Example (Simplified):
Data: 11010011101100
Generator: 1011 (4-bit example)

Sender:
11010011101100 + 000 (append 3 zeros)
= 11010011101100000

Divide by 1011:
Remainder (CRC) = 100

Send: 11010011101100100

Receiver:
11010011101100100 ÷ 1011
Remainder = 0 → Valid! ✓

Error Detection Capability:
┌───────────────────────┬──────────┐
│ Error Type            │ Detection│
├───────────────────────┼──────────┤
│ Single bit error      │ 100%     │
│ Two bit errors        │ 100%     │
│ Odd number of errors  │ 100%     │
│ Burst ≤ 32 bits      │ 100%     │
│ Burst > 32 bits      │ 99.99%   │
└───────────────────────┴──────────┘
```

### Frame Sizes Summary:

```
┌────────────────────────────────────────────────┐

├────────────────────────────────────────────────┤
│ Minimum Frame (with Preamble): 72 bytes       │
│ Minimum Frame (without Preamble): 64 bytes    │

│ Data Field:                                    │

│                                                │
│ Overhead:                                      │

│                                                │

│ Best case: 1500/1518 = 98.8%                  │
│ Worst case: 46/64 = 71.9%                     │
└────────────────────────────────────────────────┘
```

### Jumbo Frames:

```
Standard Frame: MTU = 1500 bytes
Jumbo Frame: MTU = 9000 bytes

Advantages:
✓ Less overhead (fewer frames)
✓ CPU usage কমে
✓ Throughput বাড়ে
✓ Large file transfers faster

Disadvantages:
✗ সব devices support করে না
✗ Entire path এ enable করতে হয়
✗ Error হলে বড় data retransmit

Configuration:
- Switch এ enable করতে হয়
- Network card support লাগে
- Router/Gateway config দরকার

Use Cases:
- Storage networks (SAN, NAS)
- Backup operations
- Video streaming servers
- High-performance computing
```

## 🔀 Part 4: Switch এর কার্যপ্রণালী

### Switch কি?

```
Switch = Intelligent multi-port bridge
Layer 2 device যা MAC address based forwarding করে

Hub vs Switch:
┌──────────────┬────────────┬────────────┐
│ Feature      │ Hub        │ Switch     │
├──────────────┼────────────┼────────────┤
│ Layer        │ Physical   │ Data Link  │
│ Intelligence │ None       │ MAC table  │
│ Forwarding   │ Broadcast  │ Selective  │
│ Collision    │ Yes        │ No         │
│ Speed        │ Slow       │ Fast       │
│ Price        │ Cheap      │ Moderate   │
└──────────────┴────────────┴────────────┘
```

### Switch এর Main Components:

```
┌─────────────────────────────────────┐
│            Switch                    │
│                                     │
│  ┌──────────────────────────────┐  │
│  │   MAC Address Table (CAM)    │  │
│  │   (Content Addressable       │  │
│  │    Memory)                   │  │
│  └──────────────────────────────┘  │
│               ↕                     │
│  ┌──────────────────────────────┐  │
│  │   Switching Fabric/ASIC      │  │
│  │   (Fast forwarding logic)    │  │
│  └──────────────────────────────┘  │
│               ↕                     │
│  ┌───┬───┬───┬───┬───┬───┬───┬───┐│
│  │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │ 8 ││
│  └───┴───┴───┴───┴───┴───┴───┴───┘│
│         Physical Ports              │
└─────────────────────────────────────┘
```

### MAC Address Table (CAM Table):

```
Structure:
┌──────────────────┬──────┬──────┬──────────┬──────────┐
│ MAC Address      │ Port │ VLAN │ Type     │ Age (sec)│
├──────────────────┼──────┼──────┼──────────┼──────────┤
│ AA:BB:CC:DD:EE:11│  1   │  10  │ Dynamic  │   120    │
│ AA:BB:CC:DD:EE:22│  2   │  10  │ Dynamic  │    85    │

│ AA:BB:CC:DD:EE:99│  5   │  10  │ Static   │    -     │

Fields:
1. MAC Address: Device এর physical address
2. Port: কোন port এ connected
3. VLAN: Virtual LAN ID
4. Type: Dynamic (learned) বা Static (manual)

Properties:
- CAM = Content Addressable Memory
- Hardware-based (ASIC)
- Very fast lookup (nanoseconds)
- Parallel search করতে পারে
```

### Switch Forwarding Methods:

**1. Store-and-Forward:**
```
Process:
1. পুরো frame receive করে
2. FCS check করে (error detection)
3. Error না থাকলে forward করে

Advantages:
✓ Error detection
✓ No corrupted frames forwarded
✓ বেশি reliable

Disadvantages:
✗ বেশি latency
✗ Slow (পুরো frame wait করতে হয়)

Use Case:
- High-quality networks
- Mission-critical data
- Default mode in most switches
```

**2. Cut-Through:**
```
Process:
1. শুধু destination MAC পড়ে (first 14 bytes)
2. সাথে সাথে forward শুরু করে
3. FCS check করে না

Advantages:
✓ Very low latency
✓ Fast forwarding
✓ Good for real-time applications

Disadvantages:
✗ Corrupted frames forward হতে পারে
✗ Error propagation

Use Case:
- Gaming networks
- VoIP
- Video conferencing
```

**3. Fragment-Free:**
```
Process:
1. First 64 bytes পড়ে
2. Collision check করে
3. তারপর forward করে

Logic:
- বেশিরভাগ errors প্রথম 64 bytes এ ধরা পড়ে
- Collision সবসময় প্রথম 64 bytes এ হয়

Advantages:
✓ Better than cut-through
✓ Faster than store-and-forward
✓ Balanced approach

Use Case:
- Mixed environments
- Moderate traffic networks
```

### Switch Forwarding Decisions:

**Decision Tree:**
```
Frame Received
      │
      ├─→ Learn Source MAC + Port
      │
      ├─→ Check Destination MAC
      │         │
      │         ├─→ Broadcast (FF:FF:FF:FF:FF:FF)?
      │         │         │
      │         │         └─→ YES → Flood (except source port)
      │         │
      │         ├─→ Multicast (first byte odd)?
      │         │         │
      │         │         └─→ YES → Forward to multicast group
      │         │
      │         └─→ Unicast
      │                   │
      │                   ├─→ MAC in table?
      │                   │      │
      │                   │      ├─→ YES → Forward to specific port
      │                   │      │
      │                   │      └─→ NO → Flood (unknown unicast)
      │
      └─→ Update Age Timer
```

**Case 1: Known Unicast (জানা একক গন্তব্য):**
```
Situation:
Frame: PC-A (Port 1) → PC-B (Port 3)

MAC Table:
┌──────────┬──────┐
│ MAC-A    │  1   │
│ MAC-B    │  3   │ ← এটা জানা আছে
└──────────┴──────┘

Switch Action:
1. Source MAC-A → Port 1 (refresh)
2. Dest MAC-B → Table এ আছে, Port 3
3. শুধু Port 3 এ forward ✓

Result:
   1   2   3   4
   ●   ○   ●   ○
   ↓       ↑
  PC-A    PC-B

○ = No traffic
● = Traffic flows

Efficiency: Maximum! (শুধু প্রয়োজনীয় port)
```

**Case 2: Unknown Unicast (অজানা গন্তব্য):**

```
│ (MAC-X নেই)     │
└──────────┴──────┘

Switch Action:
1. Source MAC-A → Port 1 (known)

3. Flooding করতে হবে

Forward to:
   1   2   3   4   5   6   7   8
   ●   ●   ●   ●   ●   ●   ●   ●
   ↓   ↑   ↑   ↑   ↑   ↑   ↑   ↑
  PC-A (source port ছাড়া সব port)

When PC-X replies:

- Next time direct forwarding ✓

Disadvantage:
- Unnecessary traffic on other ports

- কিন্তু প্রথমবার এটাই একমাত্র উপায়
```

**Case 3: Broadcast:**
```
Situation:

Broadcast Domain:

```

## ⚠️ Part 5: Error Detection & Correction

### Error এর প্রকারভেদ:

```
1. Single Bit Error:
   Original: 10101010
   Received: 10111010
                ↑
             One bit changed

2. Burst Error:
   Original: 10101010 11001100
   Received: 10111110 11001100
               ↑↑↑↑
           Multiple consecutive bits

3. Random Error:
   Original: 10101010 11001100 01010101
   Received: 10101011 11101100 01110101
                  ↑      ↑        ↑
            Random positions
```

### Error Detection Methods:

**1. Parity Check (সরল পদ্ধতি):**

```
Even Parity:
Data: 1011001 (4 ones)
Parity bit: 0 (make total even)
Transmitted: 10110010

Receiver:
Received: 10110010
Count ones: 4 (even) ✓ Accept

If error:
Received: 10110110
Count ones: 5 (odd) ✗ Reject

Limitations:
- শুধু odd number of errors detect করে
- Even number of errors miss করে
- কোন bit error হয়েছে জানা যায় না

Example of Failure:
Original: 10110010
Two bits flip: 10010010
Parity: Still even ✗ (error undetected)
```

**2. Checksum:**

```
Simple Checksum:
Data blocks: 25, 37, 45, 52
Sum: 25 + 37 + 45 + 52 = 159
Checksum: 159

Receiver:
Sum received data: 25 + 37 + 45 + 52 = 159
Compare with checksum: 159 = 159 ✓

If error:
Received: 25, 37, 40, 52 (45→40)
Sum: 154
Compare: 154 ≠ 159 ✗ Error detected

Internet Checksum (TCP/IP):
1. Divide data into 16-bit words
2. Add all words (with overflow wraparound)
3. Take 1's complement
4. This is checksum

Example:
Data: 0110011001100000
      0101010101010101
      1000111100001100

Step 1: Add
  0110011001100000
+ 0101010101010101
+ 1000111100001100
───────────────────
= 10100101011010001

Step 2: Wraparound carry
  0100101011010001  (lower 16 bits)
+                 1  (carry)
───────────────────
= 0100101011010010

Step 3: 1's complement
Checksum: 1011010100101101
```

**3. CRC (Cyclic Redundancy Check) - সবচেয়ে শক্তিশালী:**

```
Ethernet ব্যবহার করে CRC-32

Components:
1. Data (D): যা পাঠাতে হবে
2. Generator Polynomial (G): Fixed pattern
3. CRC bits (R): Calculated redundancy

CRC-32 Polynomial:
x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + 
x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1

Binary (33 bits):
100000100110000010001110110110111

Simplified Example (CRC-4):
Data: 1101 (4 bits)
Generator: 1011 (4 bits, so CRC = 3 bits)

Sender Side:
Step 1: Append zeros
1101 → 1101000 (append 3 zeros)

Step 2: Divide
        1010 ← Quotient (প্রয়োজন নেই)
      ┌─────
 1011 │ 1101000
       1011
       ─────
        1100
        1011
        ─────
         1110
         1011
         ─────
          101 ← Remainder (CRC)

Step 3: Replace zeros with CRC
Transmitted: 1101101

Receiver Side:
Step 1: Divide received data
        1010011
      ┌─────
 1011 │ 1101101
       1011
       ─────
        1101
        1011
        ─────
         1100
         1011
         ─────
          1111
          1011
          ─────
           100
           1011 (can't divide)
           ─────
            000 ← Remainder = 0 ✓ Valid

যদি error থাকে:
Received: 1100101 (first bit flipped)
Remainder ≠ 0 ✗ Error detected!

CRC-32 শক্তি:
✓ Single bit errors: 100%
✓ Double bit errors: 100%
✓ All odd number errors: 100%
✓ Burst errors ≤32 bits: 100%
✓ Longer bursts: 99.9999%
```

### Error Detection Performance:

```
┌──────────────────┬─────────┬──────────┬─────────┐
│ Method           │ Overhead│ Detection│ Strength│
├──────────────────┼─────────┼──────────┼─────────┤
│ Parity           │ 1 bit   │ Poor     │ ★☆☆☆☆   │
│ Checksum         │ 16-32 b │ Good     │ ★★★☆☆   │
│ CRC-16           │ 16 bits │ V.Good   │ ★★★★☆   │
│ CRC-32 (Ethernet)│ 32 bits │ Excellent│ ★★★★★   │
└──────────────────┴─────────┴──────────┴─────────┘
```

### Error Correction vs Detection:

```
Error Detection:
- শুধু error আছে কিনা জানায়
- সংশোধন করে না
- Ethernet এ ব্যবহার হয়
- Corrupted frame discard করে

Action: Retransmission (উপরের layer)

Error Correction (FEC):
- Error detect এবং correct উভয়ই করে
- Extra redundancy bits লাগে
- RAM, wireless link এ ব্যবহার হয়

Example: Hamming Code
Data: 1011
Parity bits: p1, p2, p3

Combined: p1 p2 1 p3 0 1 1

Calculate parity:
p1 (positions 1,3,5,7): 1,0,1 → p1=0
p2 (positions 2,3,6,7): 1,1,1 → p2=1
p3 (positions 4,5,6,7): 0,1,1 → p3=0

Transmitted: 0110011

If 1 bit error, receiver can:
1. Detect error
2. Find which bit
3. Correct it ✓
```

## 🚦 Part 6: Flow Control

### Flow Control কেন দরকার?

```
Problem:
┌──────────┐                 ┌──────────┐
│  Sender  │    Fast         │ Receiver │
│ 1 Gbps   │ ──────────────► │ 100 Mbps │
└──────────┘                 └──────────┘
                                  ↓
                            Buffer Overflow!
                            Data Loss!

Solution: Flow Control
- Sender কে slow down করা
- Receiver এর capacity অনুযায়ী
```

### Flow Control Methods:

**1. Stop-and-Wait:**

```
Process:
1. Sender একটি frame পাঠায়
2. Wait করে acknowledgment এর জন্য
3. ACK পেলে next frame পাঠায়

Timeline:
Sender          Network         Receiver
  │                               │
  ├─ Frame 1 ───────────────────► │
  │                               ├─ Process
  │ ◄──────────────────── ACK 1 ──┤
  │                               │
  ├─ Frame 2 ───────────────────► │
  │                               ├─ Process
  │ ◄──────────────────── ACK 2 ──┤
  │                               │

Advantages:
✓ Simple implementation
✓ No buffer overflow
✓ Guaranteed delivery

Disadvantages:
✗ Very slow
✗ Low bandwidth utilization
✗ Round-trip time waste

Efficiency:
Useful Data Time / Total Time
= Frame Transmission Time / (Frame + Propagation + ACK)

Example:
Frame: 1000 bits
Link: 1 Mbps
Propagation: 10 ms

Transmission time: 1000/1,000,000 = 1 ms
Total time: 1 + 10 + 10 = 21 ms
Efficiency: 1/21 = 4.7% ✗
```

**2. Sliding Window:**

```
Concept:
- একাধিক frames পাঠানো যায় ACK এর আগে
- Window size = কতগুলো frames

Window Size = 4:
Sender:
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │ 8 │
└───┴───┴───┴───┴───┴───┴───┴───┘
  └───────┬───────┘
       Window (can send)

Timeline:
T=0:  Send 1,2,3,4 (window full)
T=1:  Receive ACK 1 → Window slides
      Send frame 5
T=2:  Receive ACK 2 → Window slides
      Send frame 6
...

Advantages:
✓ High efficiency
✓ Better bandwidth use
✓ Pipelining

Go-Back-N:
- যদি frame 3 error
- Frame 3,4,5,6... সব retransmit

Selective Repeat:
- শুধু frame 3 retransmit
- বাকি frames buffer করে রাখে
```

**3. Credit-Based Flow Control:**

```
Receiver maintains credits:
- Credit = কতগুলো frames নিতে পারবে
- Sender credits track করে

Example:
Initial credits: 5

Sender                          Receiver
Credits: 5
  │                               │
  ├─ Frame 1 ───────────────────► │
Credits: 4                         │
  ├─ Frame 2 ───────────────────► │
Credits: 3                         │
  ├─ Frame 3 ───────────────────► │
Credits: 2                         │
  │                               ├─ Process frames
  │                               ├─ Free buffer
  │ ◄──────── Grant 3 credits ────┤
Credits: 5 (2+3)                   │
  ├─ Frame 4 ───────────────────► │

Advantages:
✓ Dynamic adjustment
✓ No buffer overflow
✓ Efficient resource use
```

**4. Pause Frames (IEEE 802.3x):**

```
Ethernet Flow Control:

যখন receiver এর buffer প্রায় full:

Receiver → Sender:
┌─────────────────────────────────┐
│ Pause Frame (MAC Control)      │
│ Type: 0x8808                    │
│ Pause Time: 65535 (quanta)     │
└─────────────────────────────────┘

Sender:
- Pause time এর জন্য transmission stop
- Timer শেষ হলে আবার শুরু

Pause Time:
- 1 quantum = 512 bit times
- 65535 quantum = max pause
- 0 = resume transmission

Full-Duplex Only:
- Half-duplex এ কাজ করে না
- Switch ports এ enable করতে হয়

Configuration (Cisco):
Switch(config-if)# flowcontrol receive on
Switch(config-if)# flowcontrol send on
```

### Buffer Management:

```
Switch Buffer:
┌──────────────────────────────────┐
│         Memory Pool              │
│  ┌────────────────────────────┐  │
│  │ Ingress Queue  (incoming)  │  │
│  ├────────────────────────────┤  │
│  │ Egress Queue   (outgoing)  │  │
│  └────────────────────────────┘  │
└──────────────────────────────────┘

Buffer Types:
1. Shared Memory:
   - সব ports share করে
   - Dynamic allocation
   - Efficient

2. Port-Based:
   - প্রতিটি port এর নিজস্ব buffer
   - Fixed allocation
   - Isolated

Queue Disciplines:
1. FIFO (First In First Out):
   - Simple
   - No prioritization

2. Priority Queue:
   - High priority first
   - QoS support

3. Weighted Fair Queue:
   - Bandwidth distribution
```

### Shared Medium এ সমস্যা:

```
Scenario: একাধিক devices একই cable/medium ব্যবহার করছে

Problem: একসাথে পাঠালে Collision!

┌────┐                    ┌────┐
│PC-A│ ─┐              ┌─ │PC-C│
└────┘  │              │  └────┘
        ├─ Shared Bus ─┤
┌────┐  │              │  ┌────┐
│PC-B│ ─┘              └─ │PC-D│
└────┘                    └────┘

যদি PC-A ও PC-B একসাথে পাঠায়:
Signal collision → Data corrupt!

Solution: Medium Access Control (MAC)
```

### 1. CSMA/CD (Carrier Sense Multiple Access with Collision Detection)

```
Used in: Traditional Ethernet (Half-Duplex)

Algorithm:
1. CS (Carrier Sense):
   - পাঠানোর আগে medium check করো
   - কেউ transmit করছে?

2. MA (Multiple Access):
   - সবাই same medium share করে

3. CD (Collision Detection):
   - Transmit করার সময়ও শুনতে থাকো
   - Collision detect করলে stop করো

Detailed Process:
┌─────────────────────────────────┐
│ Step 1: Listen (Carrier Sense)  │
│ Is medium idle?                 │
│   ├─ YES → Go to Step 2         │
│   └─ NO  → Wait until idle      │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 2: Start Transmitting      │
│ Send data                       │
│ Continue listening              │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 3: Collision Detection?    │
│   ├─ NO  → Continue, Success ✓  │
│   └─ YES → Go to Step 4         │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 4: Jam Signal              │
│ Send 48 bits jam pattern        │
│ Ensure all stations detect      │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 5: Backoff                 │
│ Wait random time                │
│ Binary Exponential Backoff      │
└─────────────────────────────────┘
           ↓
     Go to Step 1

Binary Exponential Backoff:
Attempt 1: Wait 0 or 1 slot times (random)
Attempt 2: Wait 0-3 slot times
Attempt 3: Wait 0-7 slot times
Attempt n: Wait 0 to (2^n - 1) slot times
Max attempts: 16
Max backoff: 1023 slot times

Slot Time = 512 bit times
For 10 Mbps: 51.2 microseconds
```

**Collision Detection কিভাবে:**

```
Transmitting station:
- নিজের sent signal জানে
- যা receive করছে তার সাথে compare করে

Normal:
Sent:     ━━━━━━━━━━
Received: ━━━━━━━━━━
Match! ✓ No collision

Collision:
Sent:     ━━━━━━━━━━
Received: ▓▓▓▓▓▓▓▓▓▓ (garbled)
Mismatch! ✗ Collision detected

Voltage Level Change:
- Normal signal: specific voltage
- Collision: voltage doubles/異常
```

**Minimum Frame Size Requirement:**

```
কেন 64 bytes minimum?

Collision detection এর জন্য:
- Signal পাঠিয়ে আবার ফিরে আসতে হবে
- Round-trip time এ detect করতে হবে

Formula:
Min Frame Size = 2 × Propagation Delay × Data Rate

Example:
Maximum cable: 2500 meters
Signal speed: 2×10⁸ m/s
Data rate: 10 Mbps

Propagation delay = 2500 / (2×10⁸) = 12.5 μs
Round trip = 2 × 12.5 = 25 μs

Min bits = 25 μs × 10 Mbps = 250 bits

With safety margin: 512 bits = 64 bytes

যদি frame < 64 bytes:
- Collision হতে পারে কিন্তু detect হবে না
- "Late collision" problem
```

### 2. CSMA/CA (Collision Avoidance)

```
Used in: Wi-Fi (IEEE 802.11)

কেন CD নয়, CA?
Wireless এ collision detect করা কঠিন:
- Receiver অনেক দূরে হতে পারে
- Hidden node problem
- Signal strength vary করে

Algorithm:
┌─────────────────────────────────┐
│ Step 1: Carrier Sense           │
│ Listen: Channel free?           │
│   ├─ YES → Wait DIFS            │
│   └─ NO  → Defer                │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 2: DIFS (Distributed IFS)  │
│ Wait fixed time                 │
│ Still free? → Continue          │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 3: Random Backoff          │
│ Contention Window               │
│ Select random slot              │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 4: Transmit                │
│ Send entire frame               │
│ (Can't detect collision)        │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│ Step 5: Wait for ACK            │
│   ├─ ACK received → Success ✓   │
│   └─ No ACK → Retransmit        │
└─────────────────────────────────┘

Inter-Frame Spaces (IFS):
SIFS (Short): 10 μs  (highest priority)
DIFS (Distributed): 50 μs  (normal data)
EIFS (Extended): 364 μs  (after error)
```

**Hidden Node Problem:**

```
Scenario:
       A ←─── 100m ───→ B ←─── 100m ───→ C
       
A can hear: B
B can hear: A, C
C can hear: B

Problem:
1. A starts transmitting to B
2. C can't hear A (hidden from A)
3. C thinks medium is free
4. C also transmits to B
5. Collision at B! ✗

Solution: RTS/CTS

RTS/CTS Mechanism:
A wants to send to B:

1. A → RTS (Request to Send) → B
   ┌────────────────────┐
   │ Duration: 500 μs   │ (time needed)
   └────────────────────┘
   
2. B → CTS (Clear to Send) → A
   ┌────────────────────┐
   │ Duration: 450 μs   │
   └────────────────────┘
   C hears CTS! → Must wait 450 μs

3. A → Data → B
   (C stays quiet)

4. B → ACK → A
   Now C can transmit ✓
```

### 3. Token Passing

```
Used in: Token Ring, FDDI

Concept:
- একটি special frame = Token
- শুধু token holder transmit করতে পারে
- Token circulate করে

Token Ring Topology:
    ┌────┐
    │ A  │
    └─┬──┘
      │
┌────┐│┌────┐
│ D  ││  B │
└────┴┴────┘
      │
    ┌─┴──┐
    │ C  │
    └────┘

Process:
1. Token circulates: A→B→C→D→A...
2. A wants to send:
   - Captures token
   - Attaches data
   - Sends to destination
3. Data reaches destination (C)
   - C copies data
   - Marks frame as "copied"
4. Frame returns to A
   - A removes frame
   - Releases new token
5. Token continues: B→C→D→A...

Advantages:
✓ No collision
✓ Deterministic access
✓ Fair (everyone gets turn)
✓ Predictable delay

Disadvantages:
✗ Token overhead
✗ Complex
✗ Single point of failure (token lost)

Token Lost Recovery:
- Timer mechanism
- Token monitor station
- Generates new token if lost
```

### 4. Polling

```
Concept:
- একটি master/controller
- বাকি সব slave
- Master polls each slave

Process:
Master: "Station A, আপনার data আছে?"
A: "হ্যাঁ" → Sends data
A: "না" → Next

Master: "Station B, আপনার data আছে?"
B: "হ্যাঁ" → Sends data
...

Timeline:
Master ─ Poll A ──► A
       ◄── Data ─── A
       ─ Poll B ──► B
       ◄── No ───── B
       ─ Poll C ──► C
       ◄── Data ─── C
       ...

Advantages:
✓ No collision
✓ Centralized control
✓ Priority possible

Disadvantages:
✗ Polling overhead
✗ Master = single point of failure
✗ Scalability issues

Use Cases:
- Bluetooth piconet
- Industrial networks
- Legacy mainframe systems
```

### Modern Ethernet (Full-Duplex):

```
Switch-based Networks:
- প্রতিটি port = আলাদা collision domain
- Full-duplex communication
- Send ও Receive একসাথে
- NO collision possible!

┌────────┐
│ Switch │
├─┬─┬─┬─┬┤
│ │ │ │ │ │
A B C D E

Each link:
A ↔ Switch: Dedicated, full-duplex
B ↔ Switch: Dedicated, full-duplex
...

সুবিধা:
✓ No CSMA/CD needed
✓ Maximum bandwidth
✓ Simultaneous Tx/Rx
✓ No collisions
✓ Better performance

Modern Ethernet:
- 100 Mbps+: Full-duplex সবসময়
- CSMA/CD: legacy, rarely used
- Switch: standard
```

### 6. Jumbo Frames

```
Standard Frame: 1518 bytes (1500 data)
Jumbo Frame: 9018 bytes (9000 data)

Benefits:
┌───────────────────────────────────┐
│ Standard (1500 byte payload):     │
│ 1 GB file = 699,051 frames        │
│ Headers: 699,051 × 18 = 12.6 MB   │
├───────────────────────────────────┤
│ Jumbo (9000 byte payload):        │
│ 1 GB file = 116,509 frames        │
│ Headers: 116,509 × 18 = 2.1 MB    │
└───────────────────────────────────┘

Overhead saved: 10.5 MB ✓
Less CPU processing ✓
Higher throughput ✓

Requirements:
- ALL devices must support
- MTU = 9000 on all paths
- One device doesn't support = fragmentation

Configuration:
Linux:
ip link set eth0 mtu 9000

Windows:
Network Adapter Properties → Advanced → Jumbo Frame

Use Cases:
- Storage networks
- Backup systems
- High-performance computing
- Server-to-server transfers
```

# Layer 2: Data Link Layer (ডাটা লিংক স্তর)

Data Link Layer হলো OSI মডেলের দ্বিতীয় স্তর। এটি Physical Layer এর ঠিক উপরে অবস্থিত এবং Network Layer এর নিচে।

## মূল কাজ (Primary Functions):

**১. Framing (ফ্রেমিং):**
- Network Layer থেকে আসা ডাটা প্যাকেটগুলোকে ছোট ছোট ফ্রেমে ভাগ করে
- প্রতিটি ফ্রেমে header এবং trailer যুক্ত করে
- উদাহরণ: একটি বড় ফাইলকে ছোট ছোট অংশে ভাগ করার মতো

**২. Physical Addressing (ফিজিক্যাল অ্যাড্রেসিং):**
- MAC (Media Access Control) Address ব্যবহার করে
- প্রতিটি নেটওয়ার্ক ডিভাইসের একটি unique MAC address থাকে
- এটি 48-bit address (যেমন: 00:1A:2B:3C:4D:5E)

**৩. Error Detection & Correction:**
- ডাটা ট্রান্সমিশনে কোনো error হয়েছে কিনা তা detect করে
- CRC (Cyclic Redundancy Check) method ব্যবহার করে
- প্রয়োজনে error সংশোধন করে

**৪. Flow Control:**
- sender এবং receiver এর মধ্যে ডাটা প্রবাহ নিয়ন্ত্রণ করে
- receiver যাতে overwhelmed না হয় তা নিশ্চিত করে

**৫. Access Control:**
- একই নেটওয়ার্কে একাধিক ডিভাইস থাকলে কে কখন ডাটা পাঠাবে তা নিয়ন্ত্রণ করে

## দুটি Sub-layer:

**LLC (Logical Link Control):**
- উপরের layer (Network Layer) এর সাথে যোগাযোগ করে
- Error control এবং flow control handle করে

**MAC (Media Access Control):**
- Physical Layer এর সাথে সরাসরি কাজ করে
- Physical addressing পরিচালনা করে

## বাস্তব উদাহরণ:

যখন আপনি আপনার কম্পিউটার থেকে একই Wi-Fi নেটওয়ার্কে থাকা অন্য কম্পিউটারে ফাইল পাঠান, তখন Data Link Layer:
- আপনার কম্পিউটারের MAC address থেকে অপর কম্পিউটারের MAC address এ ডাটা পাঠায়
- ডাটাকে ছোট ফ্রেমে ভাগ করে
- প্রতিটি ফ্রেম সঠিকভাবে পৌঁছেছে কিনা তা যাচাই করে

## সাধারণ ডিভাইস:
- Switch
- Bridge
- NIC (Network Interface Card)

এই layer টি নিশ্চিত করে যে, দুটি সরাসরি সংযুক্ত ডিভাইসের মধ্যে ডাটা নির্ভরযোগ্যভাবে আদান-প্রদান হয়।



### Layer 2: Data Link Layer - বিস্তারিত ব্যাখ্যা

## MAC Address - গভীর পর্যালোচনা

### MAC Address এর গঠন:

```
48-bit = 6 bytes = 12 Hexadecimal digits

Example: A1:B2:C3:D4:E5:F6

┌─────────────────┬─────────────────┐
│   OUI (24-bit)  │   NIC (24-bit)  │
│ Organizationally│ Network Interface│
│ Unique ID       │ Controller      │
└─────────────────┴─────────────────┘
   A1:B2:C3          D4:E5:F6
   (নির্মাতা)        (ডিভাইস নম্বর)
```

**OUI (Organizational Unique Identifier):**
- প্রথম 24 bit - নির্মাতা প্রতিষ্ঠান চিহ্নিত করে
- উদাহরণ: 
  - Dell: 00:14:22
  - Cisco: 00:1A:A1
  - Apple: AC:DE:48

**NIC (Network Interface Controller):**
- শেষ 24 bit - নির্দিষ্ট ডিভাইস চিহ্নিত করে
- নির্মাতা প্রতিষ্ঠান নিজেই নির্ধারণ করে

### MAC Address এর প্রকারভেদ:

**1. Unicast MAC:**
- একক ডিভাইসের জন্য
- উদাহরণ: A1:B2:C3:D4:E5:F6
- প্রথম byte এর LSB = 0

**2. Multicast MAC:**
- একাধিক ডিভাইসের জন্য
- উদাহরণ: 01:00:5E:00:00:01
- প্রথম byte এর LSB = 1

**3. Broadcast MAC:**
- সকল ডিভাইসের জন্য
- সবসময়: FF:FF:FF:FF:FF:FF

## Ethernet Frame Structure - সম্পূর্ণ বিশ্লেষণ

```
┌──────────┬──────────┬───────────┬──────┬──────────┬─────┬─────┐
│Preamble  │   SFD    │Dest. MAC  │Source│   Type/  │Data │ FCS │
│ 7 bytes  │  1 byte  │  6 bytes  │ MAC  │  Length  │     │4 byte│
│          │          │           │6 byte│  2 bytes │     │     │
└──────────┴──────────┴───────────┴──────┴──────────┴─────┴─────┘
   56 bits    8 bits     48 bits   48 bit   16 bits  46-1500  32 bit
```

### প্রতিটি অংশের কাজ:

**1. Preamble (প্রস্তাবনা) - 7 bytes:**
```
Pattern: 10101010 10101010 10101010 10101010 10101010 10101010 10101010
কাজ: 
- Receiver কে সতর্ক করে যে frame আসছে
- Clock synchronization করে
- Receiver এর timing adjust করতে সাহায্য করে
```

**2. SFD (Start Frame Delimiter) - 1 byte:**
```
Pattern: 10101011
কাজ:
- Frame এর প্রকৃত শুরু বুঝায়
- শেষ দুই bit (11) দিয়ে বুঝায় এখন ডাটা শুরু
```

**3. Destination MAC Address - 6 bytes:**
```
Example: 00:11:22:33:44:55
কাজ:
- কোথায় পাঠাতে হবে তা নির্দেশ করে
- Switch এটি পড়ে সিদ্ধান্ত নেয়
```

**4. Source MAC Address - 6 bytes:**
```
Example: A1:B2:C3:D4:E5:F6
কাজ:
- কোথা থেকে এসেছে তা জানায়
- Reply পাঠানোর জন্য দরকার
- Switch এটি দেখে MAC Table update করে
```

**5. Type/Length Field - 2 bytes:**
```
যদি মান ≥ 1536 (0x0600):
  - Type নির্দেশ করে
  - 0x0800 = IPv4
  - 0x0806 = ARP
  - 0x86DD = IPv6

যদি মান ≤ 1500:
  - Data এর length নির্দেশ করে
```

**6. Data/Payload - 46 to 1500 bytes:**
```
- প্রকৃত তথ্য থাকে
- Minimum: 46 bytes (ছোট হলে padding যোগ করা হয়)
- Maximum: 1500 bytes (MTU - Maximum Transmission Unit)
- Network Layer এর packet এখানে থাকে
```

**7. FCS (Frame Check Sequence) - 4 bytes:**
```
- CRC-32 algorithm ব্যবহার করে
- Error detection এর জন্য
- পুরো frame এর checksum

কিভাবে কাজ করে:
Sender:
1. Frame এর সব bit নিয়ে mathematical calculation করে
2. একটি 32-bit value তৈরি করে (FCS)
3. Frame এর শেষে যোগ করে

Receiver:
1. আবার একই calculation করে
2. নিজের calculated value এর সাথে received FCS মিলায়
3. মিললে ✓ (সঠিক), না মিললে ✗ (ভুল, বাতিল)
```

## Switch এর কাজ - গভীর বিশ্লেষণ

### MAC Address Table (CAM Table):

```
┌──────────────────┬──────┬──────────┬────────────┐
│ MAC Address      │ Port │ VLAN     │ Age (sec)  │
├──────────────────┼──────┼──────────┼────────────┤
│ A1:B2:C3:D4:E5:F6│  1   │    10    │    120     │
│ 00:11:22:33:44:55│  2   │    10    │     85     │
│ FF:EE:DD:CC:BB:AA│  3   │    10    │    200     │
│ 12:34:56:78:9A:BC│  4   │    20    │     45     │
└──────────────────┴──────┴──────────┴────────────┘

Aging Time: সাধারণত 300 seconds (5 minutes)
- এই সময়ে কোনো traffic না থাকলে entry মুছে যায়
```

### Switch Learning Process (শিখন প্রক্রিয়া):

**Scenario 1: নতুন ডিভাইস সংযুক্ত হলো**

```
Step 1: PC-A (MAC: AA:AA:AA:AA:AA:AA) Port 1 এ সংযুক্ত
        Frame পাঠালো

Step 2: Switch frame receive করলো
        ┌─────────────────────────────────┐
        │ এটা দেখলো:                      │
        │ Source MAC: AA:AA:AA:AA:AA:AA   │
        │ এসেছে: Port 1 থেকে             │
        └─────────────────────────────────┘

Step 3: MAC Table এ entry যোগ করলো
        ┌──────────────────┬──────┐
        │ AA:AA:AA:AA:AA:AA│  1   │
        └──────────────────┴──────┘

Step 4: Destination MAC দেখলো
        যদি Table এ না থাকে → Flooding
        যদি Table এ থাকে → সঠিক Port এ পাঠায়
```

### Switch Forwarding Decision (ফরওয়ার্ডিং সিদ্ধান্ত):

**Case 1: Unicast - Known Destination**

```
Situation:
PC-A (Port 1, MAC: AA:AA) → PC-B (Port 3, MAC: BB:BB) এ পাঠাতে চায়

Frame:
┌───────────┬───────────┬──────┐
│ Dest: BB:BB│Source: AA:AA│ Data │
└───────────┴───────────┴──────┘

Switch এর কাজ:
1. Source MAC দেখে → AA:AA, Port 1 → Table update
2. Dest MAC দেখে → BB:BB
3. Table এ খুঁজে → BB:BB আছে Port 3 এ
4. শুধু Port 3 এ পাঠায় ✓

Result: Efficient! অন্য port গুলোতে traffic যায়নি
```

**Case 2: Unicast - Unknown Destination**

```
Situation:
PC-A (Port 1) → PC-X (MAC: XX:XX) এ পাঠাতে চায়
কিন্তু XX:XX, MAC Table এ নেই!

Switch এর কাজ:
1. Source MAC দেখে → Table update
2. Dest MAC (XX:XX) দেখে → Table এ নেই!
3. Flooding করে:
   - Source port (Port 1) ছাড়া সব port এ পাঠায়
   ┌─────┐
   │Port2│ ← Frame
   │Port3│ ← Frame
   │Port4│ ← Frame
   └─────┘

4. PC-X যখন reply করবে:
   - Switch তখন XX:XX এর MAC শিখবে
   - পরবর্তীতে direct পাঠাবে
```

**Case 3: Broadcast**

```
Situation:
PC-A থেকে Broadcast (Dest: FF:FF:FF:FF:FF:FF)

Switch এর কাজ:
1. Dest MAC দেখে → FF:FF:FF:FF:FF:FF (Broadcast)
2. নিয়ম: Broadcast সবসময় সব port এ যায়
3. Source port ছাড়া সব port এ পাঠায়

ব্যবহার:
- ARP Request (IP থেকে MAC খুঁজতে)
- DHCP Discover
- Network discovery
```

**Case 4: Multicast**

```
Situation:
Streaming server multicast করছে (Dest: 01:00:5E:xx:xx:xx)

Switch এর কাজ:
1. Multicast MAC চিনে (প্রথম byte = 01)
2. IGMP snooping করে বুঝে কোন port এ listener আছে
3. শুধু interested port গুলোতে পাঠায়

Example:
Ports যেখানে multicast group member আছে:
- Port 2 ✓
- Port 5 ✓
- Port 7 ✓
শুধু এই তিন port এ পাঠাবে
```

## Real-World Example - সম্পূর্ণ Flow

### Scenario: PC-1 থেকে PC-2 তে File পাঠানো

**Network Setup:**
```
        Switch
     ┌────┴────┐
     │  1  2  3│
     │  │  │  │
    PC-1 PC-2 Router
```

**Device Information:**
```
PC-1:
- MAC: AA:BB:CC:DD:EE:11
- IP: 192.168.1.10
- Port: 1

PC-2:
- MAC: AA:BB:CC:DD:EE:22
- IP: 192.168.1.20
- Port: 2

Router:
- MAC: AA:BB:CC:DD:EE:99
- IP: 192.168.1.1
- Port: 3
```

### পদক্ষেপ ১: ARP Process

```
PC-1 জানে PC-2 এর IP (192.168.1.20)
কিন্তু জানে না MAC address!

ARP Request (Broadcast):
┌──────────────┬──────────────┬─────────────┐
│Dest: FF:FF...│Source: AA:..11│Who has     │
│(Broadcast)   │(PC-1)        │192.168.1.20?│
└──────────────┴──────────────┴─────────────┘

Switch এর কাজ:
1. Source MAC শিখলো: AA:..11 → Port 1
2. Broadcast দেখলো → সব port এ পাঠালো
   - Port 2 → PC-2 পেলো ✓
   - Port 3 → Router পেলো (ignore করলো)

PC-2 এর Response (Unicast):
┌──────────────┬──────────────┬─────────────┐
│Dest: AA:..11 │Source: AA:..22│192.168.1.20│
│(PC-1)        │(PC-2)        │is at AA:..22│
└──────────────┴──────────────┴─────────────┘

Switch এর কাজ:
1. Source MAC শিখলো: AA:..22 → Port 2
2. Dest MAC দেখলো: AA:..11 → Table এ Port 1
3. শুধু Port 1 এ পাঠালো ✓

এখন PC-1 জানে PC-2 এর MAC!
```

### পদক্ষেপ ২: File Transfer

```
Data Frame 1:
┌──────────────┬──────────────┬─────────────┐
│Dest: AA:..22 │Source: AA:..11│File data   │
│(PC-2)        │(PC-1)        │chunk 1     │
└──────────────┴──────────────┴─────────────┘
   6 bytes        6 bytes      46-1500 bytes

Switch Processing:
1. Frame আসলো Port 1 থেকে
2. Source MAC: AA:..11 → ইতিমধ্যে জানে (refresh aging timer)
3. Dest MAC: AA:..22 → Table চেক করলো
   ┌──────────┬──────┐
   │ AA:..22  │  2   │ ← পেয়ে গেলো!
   └──────────┴──────┘
4. Frame সরাসরি Port 2 এ পাঠালো
5. Port 3 তে কিছু পাঠালো না (efficient!)

Data Frame 2, 3, 4... same process
```

### পদক্ষেপ ৩: Acknowledgment

```
PC-2 থেকে ACK:
┌──────────────┬──────────────┬─────────────┐
│Dest: AA:..11 │Source: AA:..22│ACK received│
│(PC-1)        │(PC-2)        │            │
└──────────────┴──────────────┴─────────────┘

Switch:
1. AA:..22, Port 2 → Table refresh
2. AA:..11 খুঁজলো → Port 1 পেলো
3. Port 1 এ পাঠালো
```

### Switch MAC Table Final State:

```
┌──────────────────┬──────┬──────────┐
│ MAC Address      │ Port │ Age      │
├──────────────────┼──────┼──────────┤
│ AA:BB:CC:DD:EE:11│  1   │   5 sec  │ ← PC-1
```

## Error Detection - FCS বিস্তারিত

### CRC-32 Calculation:

```
Example Frame (simplified):
Data: 11010011101100

Step 1: Generator Polynomial (CRC-32)
G(x) = 33 bits (fixed polynomial)

Step 2: Sender
1. Data এর শেষে 32 bits zero যোগ করে
   11010011101100 + 00000000000000000000000000000000
2. এটিকে Generator দিয়ে ভাগ করে
3. Remainder = FCS (32 bits)
4. Original data + FCS পাঠায়

Step 3: Receiver
1. পুরো frame নিয়ে একই ভাগ করে
2. Remainder = 0 হলে ✓ সঠিক
3. Remainder ≠ 0 হলে ✗ error আছে, frame বাতিল

Error Detection Capability:
- Single bit errors: 100%
- Double bit errors: 100%
- Burst errors (up to 32 bits): 100%
- Longer burst errors: 99.9999%
```

## বিশেষ পরিস্থিতি

### Collision Domain (Hub এর ক্ষেত্রে):

```
Hub (Old technology):
    ┌───┴───┐
    1   2   3
    │   │   │
   PC-A PC-B PC-C

সমস্যা:
- যদি PC-A এবং PC-B একসাথে পাঠায়
- Collision হয় (data নষ্ট হয়)
- CSMA/CD প্রযুক্তি লাগে

Solution: Switch ব্যবহার করা
- প্রতিটি port আলাদা collision domain
- Collision হয় না!
```

### VLAN (Virtual LAN):

```
Switch with VLAN:
┌──────────────────────────────────┐
│         Switch                   │
│ Port 1-4: VLAN 10 (Sales)       │
│ Port 5-8: VLAN 20 (Engineering) │
└──────────────────────────────────┘

VLAN 10 এর PC শুধু VLAN 10 এ communicate করতে পারে
VLAN 20 এর PC শুধু VLAN 20 এ communicate করতে পারে

Benefit:
- Security ↑
- Broadcast domain ছোট
- Better organization
```

এভাবে Data Link Layer সম্পূর্ণ local network এর communication নিয়ন্ত্রণ করে! 🌐
